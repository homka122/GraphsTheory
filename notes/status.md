# Состояние работы (на 20.10.2026)

Лаба и доклад по масштабируемости распределённого Galois (D-Galois). Подробности по темам:
`notes/sssp.md`, `notes/triangle-counting.md`. Презентация — `talk/talk.pdf`, графики к ней строит
`analysis/talk_figures.py`.

## Инфраструктура

- Корень — git-репозиторий, Galois — сабмодуль `deps/Galois` (без правок, `ignore = dirty`).
  Правка для GCC 15 лежит в `patches/` и накатывается сама при `cmake`.
- Сборка: `cmake -S . -B build && make -C build -j12`, бинарники в `build/bin`.
- Профилировщики фаз раунда: `src/bfsprof`, `src/ssspprof`, `src/prprof` (собираются с флагами оригиналов,
  накладные расходы < 1%).
- Запуски: `experiments/*.sh` (пути и стартовые вершины — `experiments/common.sh`), логи — `results/<эксперимент>/`.
- Графы: `dataset/` (не в git). Для треугольников — `dataset/<g>/<g>.sym.gr` (`experiments/tc-prepare-graphs.sh`).
- Старая майская сборка — `deps/Galois/build-old`, её время с новым не смешивать.

## Правила замеров

- Всегда `GALOIS_DO_NOT_BIND_THREADS=1 mpirun -n P --map-by core --bind-to core` (это делают скрипты).
- Перед замерами при P=6 закрыть браузер, мессенджеры и не запускать ничего параллельно: P=6 занимает все ядра.
- SSSP: всегда `--maxIterations=100000000` (по умолчанию 1000 молча обрывает прогон).
- Время брать только из `Timer_N`. Таймеры Galois по раундам (`<loop>_N, Time`, `Sync_*`) округляют каждый раунд до мс.
- Один поток на процесс (`-t=1`), режим `--exec=Sync`, если не сказано иное.

## Главные результаты (P = 1…6, ускорение при P=6)

| | LiveJournal | roadNet-PA | RGG 2²¹ | USA-FLA | USA-E |
|---|---:|---:|---:|---:|---:|
| BFS | 1.14 | 4.14 | 4.13 | | |
| SSSP (лучшее Δ) | | | | 3.66 | 0.62 |
| PageRank | 1.72 | 5.24 | 5.30 | | |
| TC | 3.47 | | 5.60 | | |

- BFS на дорогах и RGG: 64–65% времени — пустые проходы по мастерам, фронт 0.2–0.3% вершин.
- LiveJournal: OEC делит поровну рёбра, а не вершины — перекос и ожидание.
- SSSP на USA-E при P=6: обмен 61% времени (зеркал 310–880 тыс. на процесс против 1–8 тыс. у FLA).
- PageRank и BFS на LiveJournal: при P=6 ребро вдвое дороже. Счётчики perf (`experiments/perf-misses.sh`):
  промахов L1 на ребро столько же, но из памяти (DRAM) данные идут в 2.6 раза чаще у PageRank
  (0.12 → 0.31 на ребро) и в 3.8 раза у BFS (0.06 → 0.23) — 6 процессов делят один L3 на 32 МБ.
